# L4LStore

A full-stack e-commerce web application built with React and Node.js. This project demonstrates a product catalogue, user authentication, shopping-cart flow, and admin-only product management backed by MongoDB.

**Live storefront:** [Open L4LStore](https://l4-l-website.vercel.app/)  
**Backend health:** [API health check](https://l4l-website.onrender.com/api/health)  
**Products API:** [Browse product data](https://l4l-website.onrender.com/api/products)  
**Source code:** [ChrisVu16-git/L4L-Website](https://github.com/ChrisVu16-git/L4L-Website)

> **Status:** The frontend is deployed on Vercel and the backend is deployed on Render. Product images are stored in Cloudflare R2. Payment processing is not currently deployed or verified for real transactions. Do not enter real payment details.

## Features

- Browse products, view product details, search, and filter the catalogue
- Register and sign in using JWT-based authentication
- Shopping-cart and checkout/order screens
- Protect authenticated-user and admin-only pages
- Admin-protected product create, read, update, and delete (CRUD) API operations
- Validate product fields and handle malformed product IDs and API errors
- Upload product images directly to Cloudflare R2 using short-lived presigned URLs
- Store each product's public image URL and R2 object key in MongoDB
- Replace product images and clean up managed R2 images when they are no longer referenced
- Backend API tests using Node.js's built-in test runner and Supertest

## Product image upload architecture

L4LStore uses Cloudflare R2 for product image storage. Images are uploaded directly from the browser to R2; the image binary does not pass through the Express backend.

1. An administrator selects an image in the React admin dashboard.
2. The frontend sends the image's MIME type to `POST /api/uploads/image/presign`. The request includes the admin's JWT.
3. The Express route checks authentication and admin authorization, validates the image type, generates a unique object key under `products/`, and returns a presigned R2 PUT URL.
4. The browser uploads the file directly to R2 using HTTP `PUT` and the matching `Content-Type` header.
5. The frontend places the returned public image URL and R2 object key into the product form. Saving the product persists these values in MongoDB.
6. When a product image is replaced or a product is deleted, the backend checks whether the old R2 object is still referenced by another product before deleting it.

The presigned URL is temporary (five minutes) and is generated by the backend. The R2 object key is used for managed-image cleanup; the public URL is used to display the image in the storefront.

### R2 configuration

Create an R2 bucket in Cloudflare and configure its public URL for image delivery. Add the following variables to `mern-shop/backend/.env`:

```env
R2_ACCOUNT_ID=your_cloudflare_account_id
R2_ACCESS_KEY_ID=your_r2_access_key_id
R2_SECRET_ACCESS_KEY=your_r2_secret_access_key
R2_BUCKET_NAME=your_r2_bucket_name
R2_PUBLIC_URL=https://your-public-r2-domain
```

Use R2 S3-compatible credentials with access to the intended bucket. Never commit real credentials, paste them into issues, or expose them in frontend environment variables. Configure the same variables in the backend hosting provider's environment settings.

For browser uploads, configure the bucket's R2 CORS policy to allow the frontend origins you actually use. The policy needs the `PUT` method and the `Content-Type` request header. For local development and the deployed storefront, the origins currently used by this project are:

- `http://localhost:5173`
- `https://l4-l-website.vercel.app`

R2 bucket CORS is separate from the Express API's CORS configuration. If the frontend can load products but image uploads fail in the browser, check the R2 bucket CORS policy as well as the API response.

## Run locally

### Prerequisites

- Node.js and npm
- MongoDB (MongoDB Atlas or a local MongoDB instance)
- A Cloudflare account with an R2 bucket and credentials for image uploads

### 1. Clone and install dependencies

From your terminal:

```bash
git clone https://github.com/ChrisVu16-git/L4L-Website.git
cd L4L-Website/mern-shop
npm install
npm run install:all
```

### 2. Configure the backend

Create `mern-shop/backend/.env` with your own values:

```env
PORT=5000
MONGODB_URI=mongodb://127.0.0.1:27017/mern-shop
JWT_SECRET=replace_with_a_long_random_secret
CLIENT_URL=http://localhost:5173

R2_ACCOUNT_ID=your_cloudflare_account_id
R2_ACCESS_KEY_ID=your_r2_access_key_id
R2_SECRET_ACCESS_KEY=your_r2_secret_access_key
R2_BUCKET_NAME=your_r2_bucket_name
R2_PUBLIC_URL=https://your-public-r2-domain
```

Replace the MongoDB and R2 placeholders with your own values. Use a strong, private `JWT_SECRET`. Never commit real credentials or `.env` files.

### 3. Configure the frontend

Create `mern-shop/frontend/.env`:

```env
VITE_API_URL=http://localhost:5000/api
```

Vite reads `VITE_*` variables at build time. Rebuild and redeploy the frontend after changing the deployed API URL.

### 4. Start the application

From `mern-shop/`:

```bash
npm run dev
```

Default local URLs:

- Frontend: http://localhost:5173
- Backend health: http://localhost:5000/api/health
- Products API: http://localhost:5000/api/products

The backend connects to MongoDB when it starts. If database-backed routes fail, check `MONGODB_URI` and the backend logs. A successful health response alone does not prove database connectivity.

## Backend tests

The backend tests use Node.js's built-in test runner and Supertest. Configure a separate test database in `mern-shop/backend/.env`:

```env
TEST_MONGO_URI=mongodb://127.0.0.1:27017/mern-shop-test
```

Ensure `MONGODB_URI`, `TEST_MONGO_URI`, `JWT_SECRET`, and the R2 environment variables are configured. Then run:

```bash
cd backend
npm test
```

Run tests only against a database intended for testing, not production data; tests may create and delete test records.

To build the frontend, run from `mern-shop/`:

```bash
npm run build
```

## API overview

All endpoints are mounted under `/api`.

| Method | Endpoint | Access | Purpose |
|---|---|---|---|
| GET | `/api/health` | Public | Check API health |
| POST | `/api/users/register` | Public | Register a user |
| POST | `/api/users/login` | Public | Sign in and receive an authentication token |
| GET | `/api/users/profile` | Authenticated | Retrieve the current user's profile |
| GET | `/api/products` | Public | List products |
| GET | `/api/products/categories` | Public | List product categories |
| GET | `/api/products/:id` | Public | Retrieve a product |
| POST | `/api/products/:id/reviews` | Authenticated | Submit a product review |
| POST | `/api/products` | Admin | Create a product |
| PUT | `/api/products/:id` | Admin | Update a product |
| DELETE | `/api/products/:id` | Admin | Delete a product |
| POST | `/api/uploads/image/presign` | Admin | Generate a short-lived R2 image upload URL |

Admin product and image-upload operations require a valid token and admin authorization. Check the route and middleware files for exact access rules, request bodies, and response formats.

## Deployment

The frontend and backend are deployed as separate services.

| Service | URL / configuration |
|---|---|
| Frontend | https://l4-l-website.vercel.app/ |
| Backend | https://l4l-website.onrender.com |
| Health check | `/api/health` |
| Frontend environment | `VITE_API_URL=https://l4l-website.onrender.com/api` |
| Backend CORS origin | `https://l4-l-website.vercel.app` |

Configure `MONGODB_URI`, `JWT_SECRET`, the five `R2_*` variables, and the required CORS origin in the backend Render service's environment settings. Configure the frontend API URL in Vercel and redeploy after changing it. Keep all secrets out of Git.
